# Decision log

This file records architecture choices for Nexo. Change a row here when the product changes; do not leave stale decisions only in chat.

| ID  | Decision           | Choice                                                                                                  | Why                                                                                               | Rejected                                                                                                                       |
| --- | ------------------ | ------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| D1  | App shape          | One Next.js App Router + TypeScript app                                                                 | Matches a real internal tool. Avoids splitting a lab into a platform.                             | Separate frontend/backend repos, Nest/Express sidecar                                                                          |
| D2  | Auth (MVP)         | Auth.js Credentials + `users` table, HTTP-only session cookie, role on the user                         | Local, seedable, Playwright `storageState` works, still a realistic Next.js pattern               | A. Supabase Auth (vendor confirmation/rate limits fight seed/CI). C. Fully custom JWT cookies (more auth bugs before any test) |
| D3  | Database           | PostgreSQL via Docker Compose + Prisma 6                                                                | One Compose service is not “complex Docker.” Prisma keeps schema + migrate + reset in npm scripts | Prisma 7+/8 driver adapters (extra moving parts before login). SQLite as default                                               |
| D4  | SQLite             | Documented fallback only                                                                                | Windows without Docker Desktop should not block Iteration 1                                       | SQLite-first (weaker types, no native sequence, not the production shape)                                                      |
| D5  | Hosting            | Local only until the app is useful                                                                      | Vercel/Supabase add accounts, env, and deploy noise                                               | Vercel from day one                                                                                                            |
| D6  | Storage            | None in MVP                                                                                             | Uploads are out of scope                                                                          | Supabase Storage, S3                                                                                                           |
| D7  | API style          | Explicit JSON REST under `/api/*` plus shared domain functions                                          | API testing is a learning goal. Server Actions alone make HTTP oracles awkward                    | Server Actions as the only mutation path                                                                                       |
| D8  | Public request id  | `NX-000001` in the URL                                                                                  | Human-readable, unique, sequential, good for test data talk                                       | UUID in the URL, numeric-only ids                                                                                              |
| D9  | Isolation oracle   | UI redirects; API uses 401 / 403 / 404. Customer reading another customer’s request is **404**, not 403 | Do not leak existence. Testers must not treat “hidden button” as security                         | Dedicated 403 HTML page; 403 for cross-customer GET                                                                            |
| D10 | Tests in this repo | No `tests/` tree until after Iteration 5                                                                | You build the suite. Docs describe challenges, not spoilers                                       | A pre-written Playwright framework                                                                                             |
| D11 | Prisma version     | Pin Prisma **6.19.x** (`prisma-client-js`, `url` in schema)                                             | Classic Next.js + Prisma labs and reset scripts stay simple                                       | Prisma 7/8 (`prisma.config.ts` + `@prisma/adapter-pg`)                                                                         |
| D12 | Auth.js timing     | Iteration 2                                                                                             | Skeleton (I1) must boot first; sessions after pages exist                                         | Wiring sessions in Iteration 1                                                                                                 |
| D13 | Auth.js version    | `next-auth@5.0.0-beta.32` (Auth.js v5), JWT session, Credentials only                                   | Matches D2. No Prisma adapter (Credentials + JWT). Cookie via Auth.js + thin `/api/auth/*`        | next-auth v4 pages router; database sessions                                                                                   |
| D14 | Route protection   | Next.js 16 `proxy.ts` + Auth.js `authorized` callback                                                   | `middleware.ts` is deprecated in Next 16                                                          | Express-style middleware; protecting only in the page                                                                         |

## Iteration 2 follow-through

- Env pattern: `.env.example` → `.env.local` (Next.js). Prisma CLI scripts load `.env.local` via `dotenv-cli`.
- Seed: roles + three users (`npm run db:seed`). Request fixtures wait for Iteration 5.
- Login UI posts to `POST /api/auth/login`. Auth.js still owns `/api/auth/[...nextauth]`.
